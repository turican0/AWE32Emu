AWEDUMP - verification in 86Box (2026-09-13)
============================================

Status: WORKS. The source (awedump.asm) and AWEDUMP.COM match: the tables
init1..init4 lie in the COM at offset 2649, the file length ends exactly at
the end of the 32 kB buffer, all texts are inside. Nothing needed fixing.

Run
---
A DOS VM in 86Box (MS-DOS 6.22, SBAWE32 drivers), AUTOEXEC:

    C:\AWEDUMP.COM 620 < C:\KEY.TXT > C:\DUMPLOG.TXT

(KEY.TXT = "Y" + CRLF instead of a key press; the output goes to
DUMPLOG.TXT, so only "File not found" from DEL stays on the VM screen.)
After 60 s:

    AWEDUMP - EMU8000 ROM dumper.  Base port: 0x0620
    EMU8000-like chip responded at this base.
    Press a key to dump ROM to AWE32ROM.BIN (ESC to abort)...Y
    Dumping 1 MB ................................
    Done: AWE32ROM.BIN written (1,048,576 bytes).

Result
------
AWE32ROM.BIN (md5 4109fb079dcb1a09c258675c2de0466d) is byte for byte the
same as the ROM as 86Box holds it IN MEMORY. Against the file awe32.raw (md5
30b76c45ca0712418239d2b15c65881a) it is shifted by one word - that is NOT a
dumper error:

    86Box emu8k_init(): "AWE-DUMP creates ROM images offset by 2 bytes, so if
    we detect this then correct it" - when rom[3]==0x314D and rom[4]==0x474D,
    it shifts the ROM down by a word and clears the last word.

awe32.raw starts with 1234 0032 2E38 314D 474D, so 86Box shifts it and has
0032 at address 0. AWEDUMP (drops the first SMLD read, like ALSA size_dram)
reads exactly that.

What follows for a dump from a real card: a correct dump starts with the
word 0032 (without the leading 1234). If it started with 1234 0032, the
dumper reads one word early and it should be reported.

Comparison: python romcompare.py AWE32ROM.BIN [reference.raw]
            (detects a match, a shift by N words, swapped bytes, every second
            word, repeated blocks)

Small issues in the source (they did not show in 86Box)
------------------------------------------------------
- The file write (int 21h/40h) checks neither the error nor the number of
  bytes written: on a full disk it prints "Done" with an incomplete file. So
  always check the size of 1 048 576 B after the run.
- It waits for a key (int 21h/01h); for a batch run redirecting the input is
  enough.
- The parameter is only a hex number (620), not "E620".
- Rebuilding needs NASM.
